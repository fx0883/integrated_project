# 菜单管理功能实施计划

## 1. 概述

本文档提供了在现有系统中为超级管理员添加菜单管理功能的详细实施计划。菜单管理功能将允许超级管理员查看、创建、编辑和删除系统中的菜单项，实现动态菜单配置。

## 2. 需求分析

### 2.1 功能需求

- 为超级管理员提供专用的菜单管理界面
- 支持菜单的增删改查操作
- 支持菜单树形结构的可视化和编辑
- 支持调整菜单顺序
- 支持修改菜单图标、权限等属性
- 实时预览菜单修改效果

### 2.2 用户角色

- **超级管理员**：拥有完整的菜单管理权限，可以进行所有操作
- **系统管理员**：可以查看菜单结构，但无法修改
- **普通用户**：无权访问菜单管理界面

## 3. 系统架构分析

### 3.1 现有系统菜单实现

当前系统基于Vue 3、Vue Router和Pinia实现菜单功能：

- 菜单数据通过API获取(`/api/v1/menus/`和`/api/v1/menus/tree/`)
- `usePermissionStore`负责管理菜单状态和缓存
- 菜单渲染通过`lay-sidebar`组件完成
- 已实现权限控制组件`Auth`和`Perms`

## 4. 实施步骤

### 4.1 API模块扩展

1. 在`src/api/modules`中创建`menu.ts`，实现菜单管理相关API：
   - 获取菜单列表
   - 获取菜单树
   - 创建菜单
   - 更新菜单
   - 删除菜单
   - 调整菜单顺序

### 4.2 菜单管理页面开发

1. 在`src/views`下创建`menu`目录，包含以下文件：
   - `index.vue` - 菜单列表页面
   - `components/MenuTree.vue` - 树形菜单展示组件
   - `components/MenuForm.vue` - 菜单编辑表单组件
   - `components/IconSelector.vue` - 图标选择器组件

### 4.3 路由配置

1. 在`src/router/modules`目录下创建`menu.ts`：
   ```typescript
   import { $t } from "@/plugins/i18n";
   const Layout = () => import("@/layout/index.vue");

   export default {
     path: "/menu-management",
     name: "MenuManagement",
     component: Layout,
     meta: {
       icon: "menu",
       title: "菜单管理",
       rank: 10,
       roles: ["super_admin"] // 只对超级管理员可见
     },
     children: [
       {
         path: "list",
         name: "MenuList",
         component: () => import("@/views/menu/index.vue"),
         meta: {
           title: "菜单列表",
           roles: ["super_admin"]
         }
       }
     ]
   };
   ```

### 4.4 Pinia Store扩展

1. 在`src/store/modules`下创建`menu.ts`，用于管理菜单数据：
   - 加载菜单列表和树形结构
   - 处理菜单的增删改操作
   - 管理表单状态和编辑状态

### 4.5 组件开发规范

1. **菜单列表页面**
   - 左侧树形菜单结构展示
   - 右侧菜单详情和编辑表单
   - 支持拖拽排序功能

2. **菜单表单组件**
   - 支持所有菜单属性的编辑
   - 通过Tab分类不同属性（基本信息、权限设置、外观设置等）
   - 实时表单验证

3. **图标选择器**
   - 支持选择Element Plus内置图标
   - 支持上传自定义图标
   - 图标预览功能

## 6. 权限控制

1. **路由级权限**：
   - 在路由配置中设置`roles: ["super_admin"]`，确保只有超级管理员可访问

2. **组件级权限**：
   - 使用`Auth`组件控制关键操作按钮的显示
   - 示例：`<Auth value="menu:manage:edit"><el-button>编辑</el-button></Auth>`

3. **API权限**：
   - 确保后端API已实施权限控制，验证用户是否为超级管理员

## 7. 数据流向

```
┌───────────────┐      ┌───────────────┐      ┌───────────────┐
│  API请求/响应  │◄────►│  菜单Store    │◄────►│  UI组件      │
└───────────────┘      └───────────────┘      └───────────────┘
```

1. 用户打开菜单管理页面时，从API获取菜单数据
2. 数据存储在Pinia中的菜单Store中
3. UI组件从Store中读取数据并显示
4. 用户操作触发Store中的actions，进行增删改查
5. 操作成功后，更新本地Store数据并刷新菜单

## 8. 实施计划

### 阶段一：基础开发（预计3天）

1. 创建API模块
2. 实现菜单管理Store
3. 开发菜单列表页面基本结构
4. 配置菜单管理路由

### 阶段二：功能开发（预计5天）

1. 完善菜单树组件，支持展示和选择功能
2. 开发菜单表单组件，支持菜单的增删改功能
3. 实现图标选择器组件
4. 添加表单验证和错误处理

### 阶段三：优化及测试（预计2天）

1. 添加拖拽排序功能
2. 完善权限控制
3. 优化用户交互体验
4. 进行功能测试和修复bug

## 9. 注意事项

1. **数据一致性**：修改菜单后需要确保前端路由和菜单显示同步更新
2. **性能优化**：避免频繁API调用，合理使用缓存
3. **错误处理**：添加友好的错误提示和回滚机制
4. **用户体验**：实时预览菜单变更效果
5. **安全性**：严格控制菜单管理权限，防止未授权访问
