# CMS系统架构文档

## 1. 系统概述

CMS（内容管理系统）是一个多租户架构的内容管理平台，支持文章、分类、标签和评论等核心功能。系统采用Django和Django REST Framework构建，支持多租户隔离和细粒度的权限控制。

## 2. 系统架构

### 2.1 整体架构

CMS系统采用分层架构设计：

1. **表示层**：REST API接口，负责与前端交互
2. **业务逻辑层**：视图集和序列化器，处理业务逻辑
3. **数据访问层**：模型和查询集，处理数据存取
4. **基础设施层**：中间件、认证和权限控制

### 2.2 权限控制架构

权限控制是CMS系统的核心组件，主要由以下部分组成：

1. **认证机制**：基于JWT的用户认证
2. **租户中间件**：处理租户上下文和租户ID验证
3. **权限类**：定义不同资源的访问权限规则
4. **视图集基类**：提供多租户支持的通用视图集

## 3. 多租户支持

### 3.1 租户模型

每个租户在系统中都有独立的数据隔离：

- 每个数据模型都包含`tenant`外键字段
- 所有查询都会根据当前租户进行过滤
- 创建数据时自动关联当前租户

### 3.2 租户上下文

系统使用线程局部变量存储当前请求的租户上下文：

- 设置当前租户
- 获取当前租户
- 清除租户上下文

### 3.3 租户中间件

`TenantMiddleware`负责从请求中提取租户信息并设置租户上下文：

1. 从`X-Tenant-ID`请求头获取租户ID
2. 从认证用户的关联租户获取租户ID
3. 验证租户ID的有效性和用户权限
4. 设置租户上下文和请求对象的租户ID

## 4. 权限控制实现

### 4.1 权限控制流程

CMS系统的权限控制遵循以下规则：

#### 查询操作（GET请求）
- 不需要token认证，允许匿名访问
- 需要在请求头中包含`X-Tenant-ID`参数来指定租户
- 如果有token，则通过token获取租户ID
- 如果没有token，则检查`X-Tenant-ID`是否存在，存在则继续，不存在则报错

#### 修改操作（POST、PUT、PATCH、DELETE等）
- 需要token认证
- 通过token获取用户关联的租户ID
- 如果用户没有关联租户ID，则报错
- 超级管理员因无关联租户ID，不能操作CMS数据

### 4.2 权限类层次结构

```
CMSBasePermission
├── ArticlePermission
├── CategoryPermission
├── TagPermission
├── CommentPermission
├── ArticleVersionPermission
├── ArticleMetaPermission
├── ArticleStatisticsPermission
└── InteractionPermission
```

### 4.3 视图集基类

`TenantModelViewSet`是所有CMS视图集的基类，提供以下功能：

1. 根据租户ID过滤查询集
2. 创建对象时自动设置租户ID
3. 验证对象所属租户与用户租户是否匹配

## 5. 数据模型

CMS系统的核心数据模型包括：

- **Article**：文章模型，包含标题、内容、状态等字段
- **Category**：分类模型，支持树形层次结构
- **Tag**：标签模型，可分组管理
- **Comment**：评论模型，支持树形结构的评论回复
- **ArticleVersion**：文章版本历史
- **ArticleStatistics**：文章统计数据
- **Interaction**：用户互动记录

所有模型都包含`tenant`字段，用于多租户数据隔离。

## 6. API接口设计

API接口遵循RESTful设计原则，主要包括：

1. **文章管理**：CRUD操作、版本管理、统计数据
2. **分类管理**：CRUD操作、树形结构
3. **标签管理**：CRUD操作、分组管理
4. **评论管理**：CRUD操作、审核流程

所有API端点都支持租户隔离和权限控制。

## 7. 修改方案

为了实现新的权限控制需求，需要对以下组件进行修改：

### 7.1 租户中间件修改

修改`TenantMiddleware`以支持新的权限控制流程：

1. 对GET请求，允许匿名访问但需要租户ID
2. 对其他请求，要求认证并验证用户关联租户

### 7.2 权限类修改

修改`CMSBasePermission`类：

1. 对GET请求，允许匿名访问但验证租户ID
2. 对其他请求，要求认证并验证用户关联租户

### 7.3 视图集修改

修改`TenantModelViewSet`基类：

1. 更新`get_queryset`方法以支持匿名访问的租户过滤
2. 更新`perform_create`等方法以验证用户关联租户

## 9. 测试计划

为确保修改后的权限控制机制正常工作，需要进行以下测试：

1. **匿名访问测试**
   - 不提供租户ID的GET请求应该失败
   - 提供租户ID的GET请求应该成功
   - 尝试执行非GET请求应该失败

2. **认证用户测试**
   - 未关联租户的用户执行非GET请求应该失败
   - 关联租户的用户执行与其租户匹配的请求应该成功
   - 关联租户的用户执行与其租户不匹配的请求应该失败

3. **超级管理员测试**
   - 未关联租户的超级管理员执行CMS操作应该失败
   - 关联租户的超级管理员执行与其租户匹配的请求应该成功

4. **租户管理员测试**
   - 租户管理员应该能够管理其租户内的所有资源
   - 租户管理员不能管理其他租户的资源

5. **普通用户测试**
   - 普通用户应该能够创建和管理自己的资源
   - 普通用户不能管理其他用户的资源

### 11.2 实体说明

- **Article**: 核心内容实体，包含标题、正文、状态等信息
- **Category**: 分类实体，支持层级结构(树状)
- **Tag**: 标签实体，可归类到标签组
- **TagGroup**: 标签分组，用于组织管理标签
- **Comment**: 评论实体，支持嵌套回复
- **ArticleMeta**: 文章元数据，存储SEO相关信息
- **ArticleStatistics**: 文章统计数据，如阅读量、点赞数
- **ArticleVersion**: 文章版本记录，存储历史变更
- **Interaction**: 用户互动记录，如点赞、收藏
- **AccessLog**: 访问记录，跟踪文章访问情况
- **UserLevel**: 用户等级定义，控制用户权限
- **OperationLog**: 操作日志，记录系统关键操作

## 19. 安全设计

CMS系统实现了多层次安全机制：

1. **认证系统**: JWT令牌认证
2. **权限控制**: 基于角色的访问控制(RBAC)
3. **租户隔离**: 严格的数据隔离
4. **输入验证**: 所有用户输入严格验证
5. **CSRF保护**: 防止跨站请求伪造
6. **API限流**: 防止DoS攻击

## 20. 性能优化设计

CMS系统针对性能做了以下优化：

1. **数据库索引**: 关键查询字段添加索引
2. **缓存机制**: 支持内容缓存
3. **分页机制**: 大数据集合分页加载
4. **查询优化**: 使用select_related和prefetch_related
5. **延迟加载**: 非关键数据延迟加载
